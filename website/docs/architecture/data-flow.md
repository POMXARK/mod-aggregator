# Потоки данных

Описание основных потоков данных между компонентами системы.

## Загрузка и парсинг страницы

### Полный процесс

```
1. Пользователь → Frontend (PageViewer)
   ↓
2. Frontend вызывает Tauri команду `fetch_page`
   ↓
3. Backend проверяет кэш (если force_refresh=false)
   ↓
4. Если кэш отсутствует/устарел:
   a. Backend загружает HTML с сервера (reqwest)
   b. Сохраняет в кэш (app_data_dir/cache/{site_id}/{hash}.html)
   ↓
5. Backend возвращает HTML во Frontend
   ↓
6. Frontend отображает HTML в iframe
   ↓
7. Пользователь выбирает элементы на странице
   ↓
8. Frontend вызывает `parse_page` с выбранными селекторами
   ↓
9. Backend парсит HTML используя конфигурацию парсера
   ↓
10. Backend возвращает результат парсинга
   ↓
11. Frontend отображает результат
```

### Кэширование

- **Местоположение:** `{app_data_dir}/cache/{site_id}/{url_hash}.html`
- **Структура:** Каждый сайт имеет свою папку для кэша
- **Обновление:** Кэш обновляется при `force_refresh=true` или отсутствии файла
- **Очистка:** Через команду `clear_page_cache()`

## Создание парсера

### Процесс построения парсера

```
1. Пользователь открывает ParserBuilder
   ↓
2. Пользователь добавляет ноды (Selector, Extract, Filter, etc.)
   ↓
3. Пользователь настраивает ноды (селекторы, атрибуты)
   ↓
4. Frontend строит граф нод
   ↓
5. Пользователь сохраняет конфигурацию
   ↓
6. Frontend вызывает `add_site` или `update_site` с parser_config
   ↓
7. Backend валидирует конфигурацию парсера
   ↓
8. Backend сохраняет в базу данных (таблица sites, поле parser_config)
   ↓
9. Frontend обновляет список сайтов
```

### Структура конфигурации парсера

```typescript
interface ParserConfig {
  root: string;  // Корневой селектор
  children: {
    [fieldName: string]: string | ParserNode;
  };
}

interface ParserNode {
  selector: string;
  attribute?: string;  // Для извлечения атрибутов (@href, @src)
  children?: Record<string, string | ParserNode>;  // Вложенные селекторы
}
```

## Проверка обновлений модов

### Процесс проверки обновлений

```
1. Пользователь нажимает "Проверить обновления"
   ↓
2. Frontend вызывает `check_updates(site_id)`
   ↓
3. Backend загружает список модов для сайта из БД
   ↓
4. Для каждого мода:
   a. Загружает страницу мода (fetch_page)
   b. Парсит страницу используя конфигурацию парсера
   c. Извлекает версию мода
   d. Сравнивает с версией в БД
   ↓
5. Если версия изменилась:
   a. Создает запись в таблице notifications
   b. Обновляет версию мода в БД
   ↓
6. Backend возвращает список обновлений
   ↓
7. Frontend отображает уведомления
```

## Сохранение страниц с версионированием

### Процесс сохранения

```
1. Пользователь сохраняет страницу
   ↓
2. Frontend вызывает `save_page_local(url, html, site_id)`
   ↓
3. Backend создает запись в таблице saved_pages:
   - site_id: привязка к сайту
   - url: URL страницы
   - html: HTML содержимое
   - version: timestamp создания
   ↓
4. Backend возвращает SavedPage объект
   ↓
5. Frontend обновляет UI
```

### Получение версий

- `get_saved_page_for_site(site_id)` - последняя версия
- `get_saved_page_versions(site_id)` - все версии
- `delete_saved_page_version(id)` - удаление конкретной версии

## Синхронизация состояния

### Frontend → Backend

- Все изменения данных проходят через Tauri команды
- Frontend не хранит состояние данных (только UI состояние)
- При загрузке данных вызываются команды `get_sites()`, `get_mods()`, etc.

### Backend → Frontend

- Backend возвращает актуальные данные из БД
- Frontend обновляет UI на основе полученных данных
- Ошибки обрабатываются и отображаются пользователю

## Обработка ошибок

### Типы ошибок

1. **Сетевые ошибки**
   - Обрабатываются в `fetch_page`
   - Используется кэш, если доступен
   - Возвращается понятное сообщение об ошибке

2. **Ошибки парсинга**
   - Валидация селекторов перед парсингом
   - Частичные результаты при ошибках парсинга
   - Логирование ошибок для отладки

3. **Ошибки базы данных**
   - Обработка через `Result<T, String>`
   - Возврат понятных сообщений об ошибках
   - Логирование для отладки

### Поток обработки ошибок

```
Ошибка → Backend → Result<T, String> → Frontend → UI (сообщение об ошибке)
```
