# Документация проекта

Эта папка содержит структурированную документацию проекта для AI агентов и разработчиков.

## Структура документации

```
docs/
├── README.md                    # Этот файл - обзор документации
├── architecture/               # Архитектурная документация
│   ├── overview.md            # Общий обзор архитектуры
│   ├── frontend.md            # Архитектура frontend
│   ├── backend.md             # Архитектура backend
│   └── data-flow.md           # Потоки данных
├── api/                        # API документация
│   ├── tauri-commands.md      # Tauri команды
│   ├── frontend-api.md        # Frontend API
│   └── database-schema.md     # Схема базы данных
├── guides/                     # Руководства
│   ├── development.md         # Руководство по разработке
│   ├── testing.md             # Руководство по тестированию
│   └── deployment.md         # Руководство по развертыванию
├── components/                 # Документация компонентов
│   ├── parser-builder.md      # Конструктор парсеров
│   ├── page-viewer.md         # Просмотр страниц
│   └── sites-manager.md       # Управление сайтами
└── examples/                   # Примеры использования
    ├── parser-config.md       # Примеры конфигураций парсеров
    └── api-usage.md           # Примеры использования API
```

## Как Cursor использует эту документацию

Cursor AI автоматически индексирует и использует файлы из папки `docs/` для:
- Понимания архитектуры проекта
- Генерации кода в соответствии с паттернами проекта
- Предложения улучшений на основе документации
- Ответов на вопросы о проекте

### Использование в чате

Вы можете ссылаться на документацию в чате Cursor:
- `@docs` - ссылка на всю папку docs
- `@docs/architecture/overview.md` - ссылка на конкретный файл
- `@docs/api/tauri-commands.md` - ссылка на API документацию

### Автоматическое использование

Cursor автоматически использует документацию при:
- Генерации нового кода
- Рефакторинге существующего кода
- Ответах на вопросы о проекте
- Предложении улучшений

## Правила обновления документации

1. **Обновляй документацию вместе с кодом**
   - При изменении API - обновляй `api/`
   - При изменении архитектуры - обновляй `architecture/`
   - При добавлении компонентов - обновляй `components/`

2. **Используй Markdown формат**
   - Все файлы должны быть в формате `.md`
   - Используй стандартный Markdown синтаксис
   - Добавляй примеры кода с подсветкой синтаксиса

3. **Структурируй информацию**
   - Используй четкие заголовки
   - Группируй связанную информацию
   - Добавляй примеры и диаграммы

4. **Документируй для AI**
   - Объясняй "почему", а не только "что"
   - Описывай контекст и намерения
   - Указывай связи между компонентами
   - Приводи примеры использования

## Связь с правилами Cursor

Документация в `docs/` дополняет правила из `.cursor/rules/`:
- `.cursor/rules/` - правила написания кода
- `docs/` - описание того, что уже написано и как это работает

Оба источника используются AI для лучшего понимания проекта.
