# Логика работы парсера

## Общая схема работы

1. **Фронтенд (ParserRunner.svelte)**
   - Пользователь нажимает "Запустить парсер"
   - Создается `AbortController` для возможности остановки
   - Загружается HTML страница через Tauri команду `fetch_page`
   - Вызывается Tauri команда `test_parser_from_nodes` с HTML, узлами и ребрами графа

2. **Бэкенд (Rust - test_parser_from_nodes)**
   - Парсит HTML в DOM дерево через библиотеку `scraper`
   - Находит корневой selector node (узел без входящих связей)
   - Извлекает CSS селектор из корневого узла
   - Находит все элементы на странице по этому селектору
   - Применяет ограничения (max_elements, timeout_millis)
   - Для каждого найденного элемента:
     - Находит связанные extract узлы
     - Извлекает данные по селекторам extract узлов
     - Собирает результаты в JSON объекты
   - Возвращает результаты, диагностику и статистику

## Проблема с остановкой парсера

**Текущая реализация:**
- Фронтенд использует `AbortController` для отмены промисов
- `AbortController.abort()` отменяет только JavaScript промисы
- **Rust код выполняется синхронно в цикле обработки элементов**
- Когда Rust код уже начал выполнение, `AbortController` не может его остановить

**Почему парсер не останавливается:**
1. `test_parser_from_nodes` - это синхронная функция в Rust
2. После вызова `invoke('test_parser_from_nodes', ...)` промис ждет завершения Rust кода
3. Rust код выполняется в цикле `for (index, element) in test_elements.iter().enumerate()`
4. Даже если мы вызовем `abortController.abort()`, промис уже "привязан" к выполнению Rust кода
5. Rust код продолжит работу до завершения всех элементов или таймаута

**Решение:**
- Текущая реализация уже использует таймаут на уровне Rust (`timeout_millis`)
- Проверка таймаута происходит перед обработкой каждого элемента
- Это означает, что парсер остановится при достижении таймаута
- Но **немедленная остановка по кнопке "Остановить" невозможна** без изменения архитектуры

**Возможные улучшения:**
1. Разбить обработку на батчи и периодически проверять флаг отмены (требует изменения Rust кода)
2. Использовать worker thread в Rust с каналом для сигнала остановки (сложная архитектура)
3. Принять ограничение: парсер останавливается только по таймауту или завершению обработки

## Текущий механизм остановки

1. Пользователь нажимает "⏹️ Остановить"
2. Вызывается `stopParser()` в `ParserRunner.svelte`
3. `abortController.abort()` вызывается, что устанавливает `signal.aborted = true`
4. Проверки `isCancelled || signal.aborted` в `runParser()` предотвращают дальнейшие действия
5. **НО** если `invoke('test_parser_from_nodes')` уже выполняется, Rust код продолжит работу
6. Rust код проверяет таймаут только перед обработкой каждого элемента
7. Парсер остановится либо при завершении всех элементов, либо при достижении таймаута

## Рекомендации

- Таймаут по умолчанию 60 секунд - это разумное ограничение
- Пользователь может уменьшить таймаут в настройках для более быстрой остановки
- Кнопка "Остановить" работает для отмены операций получения HTML и предотвращения запуска парсера
- Если парсер уже запущен, он остановится автоматически при достижении таймаута

## Медленный режим (Slow Mode)

**Описание:**
Медленный режим позволяет наблюдать за обработкой элементов парсера в реальном времени. Каждый элемент обрабатывается с задержкой между ними, что позволяет видеть прогресс выполнения.

**Как работает:**
1. Пользователь включает "Медленный режим" в настройках парсера
2. Устанавливает задержку между элементами (100-5000 мс)
3. При запуске парсера:
   - Обрабатывается первый элемент
   - Выводится сообщение в диагностике: "✅ Обработан элемент #1 из N (извлечено X полей)"
   - Происходит задержка (если установлена)
   - Обрабатывается следующий элемент
   - И так далее до завершения всех элементов

**Настройки:**
- **Медленный режим** (чекбокс) - включает/выключает режим
- **Задержка между элементами** (100-5000 мс) - время паузы между обработкой элементов
  - Рекомендуемое значение: 500-1000 мс для комфортного наблюдения
  - Минимум: 100 мс
  - Максимум: 5000 мс (5 секунд)

**Преимущества:**
- Видно прогресс обработки в реальном времени
- Можно отследить, на каком элементе произошла ошибка
- Полезно для отладки парсеров на больших списках элементов
- Диагностика обновляется после обработки каждого элемента

**Ограничения:**
- Увеличивает общее время выполнения парсера
- Не влияет на возможность остановки парсера (останавливается по таймауту)
